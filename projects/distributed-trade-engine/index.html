The Problem

Correctness is harder than consuming messages

Real event-processing systems must assume duplicates, transient failures, traffic spikes, partial outages, and drift between streaming state and an authoritative source. The engine models those failure modes directly.

01

Idempotent Processing

Immutable event IDs prevent duplicate delivery from reapplying business side effects.

02

Bounded Concurrency

An asyncio semaphore caps in-flight work so traffic spikes cannot create unlimited pressure on downstream dependencies.

03

Retries + DLQ

Transient failures use exponential backoff; exhausted events move to an explicit dead-letter queue for investigation or replay.

04

Reconciliation

A separate comparison engine detects missing, stale, and unexpected trades against an authoritative snapshot.

Engineering Decisions

Built for interview-level discussion

At-least-once delivery

The design does not pretend infrastructure gives free exactly-once semantics. Idempotency is handled at the application boundary.

Explicit state machine

Trades move through RECEIVED → VALIDATED → ENRICHED → SETTLED, with invalid transitions rejected.
